## 2. Face, forms and simulated reward

One original geometric face is displayed per trial: a circle, two circular eyes and one centered horizontal mouth line. Use an original SVG viewBox `0 0 120 120`, face circle centered `(60,60)` with radius `48`, eyes centered `(44,48)` and `(76,48)` with radius `4`, and a dark mouth at `y=77` with stroke width `3` and round caps. The mouth is centered at `x=60`. Standard short/long line lengths are `22/30` SVG units. The separately labeled visual accommodation uses `18/38`; all other task logic and its recorded form number are the same, but standard and accommodation results are never described as equivalent. The face must occupy at least `240` CSS pixels in a visible connected layout during scored play. Use at least 7:1 face/background contrast. The face conveys no answer by color, label, sound, DOM attribute or hidden text during the timed trial. The untimed guide shows both mouth lengths with labels and explains the answer.

Each fixed form `LM1`–`LM6` has **90 scored trials**, internally grouped into three sets of 30 for checkpointing. Every set contains 15 short and 15 long mouths; each form has 45 of each. The rich side is short for odd numbered forms and long for even numbered forms. Every form has **16 preassigned reward opportunities:** 12 on the rich side, four on the lean side. Each set has four rich opportunities; its lean count is one, one or two, with the two-opportunity set rotating by form number. Opportunity positions are never adjacent, including across set boundaries. A reward of **50 simulated cents** is given only if the candidate classifies an eligible trial correctly before its deadline. An incorrect or omitted eligible trial pays zero; correct ineligible trials also pay zero. There is no loss or negative balance. Maximum possible bank is 800 cents. The hidden opportunity schedule does not change in response to performance. The candidate is told that some correct answers earn a simulated reward and others do not; no incorrectness is implied by a silent trial.

`scripts/generate-lengths-mouth-forms.mjs` is the only form constructor. For form number 1–6 its unsigned xorshift32 seed is `0x1e470101 + number − 1`, with state update `state ^= state << 13; state ^= state >>> 17; state ^= state << 5` and unsigned conversion after the step. For each set, Fisher–Yates shuffle 15 `short` and 15 `long` cards from index 29 to 1 with `next() % (index+1)`; reject until no four-mouth run in the combined prefix and the set has 12–22 switches. Fail after 100,000 candidates. Then shuffle the indices of the 15 rich trials and separately the 15 lean trials; take the first four rich and first one or two lean indices, sort them, reject and redraw until no two selected positions are adjacent or adjacent to the previous set's last rewarded position. A rejected proposal consumes its draws. Fail after 100,000 proposals. There is no live random selection or adaptation. The output is `ASSESSMENT_PRACTICE_LENGTHS_MOUTH_FORMS_V1_1.json`, containing `version`, `baseSeed`, all six forms, and SHA-256 of compact JSON `{version,baseSeed,forms}`. A missing, altered or unsupported manifest blocks scored admission. The scored sequence, reward schedule and rich side must not be disclosed before or during play.

The fixed form payload SHA-256 is `ae92d69cffeb20cac02d3be5648ee8e162e575583c55b03dfe3cd2301c0846e9`. The fixture-file compact JSON SHA-256 is `5f5656bc35cff5b776075968b88ab369a4820af8233c741801044d42f28b50a8`. The accepted six orders differ in 34–52 mouth positions pairwise; this is variety, not calibrated equivalence.

An atomic accepted arm assigns the next numbered form using a V1.1 family counter: `((counter mod 6)+1)`; standard and accommodation have separate counters but use the same numbered order. Rejected or uncommitted arms consume nothing; a committed arm consumes one position even with zero exposure. Retries with the same request ID are idempotent. Individual deletion does not rewind counters. Form repeats after six arms and is labeled repeated. Alternate forms provide variety, not calibrated difficulty or improvement evidence.

## 3. Candidate journey, controls and timing

Library → brief original guide → two untimed labeled examples → two understanding questions (short/long mapping and what a silent trial means) → input/visual setup and check → readiness → 90 trials → report/history. Wrong quiz answers reveal the rule and can be retried without consuming a form. Guide, quiz, setup and readiness are untimed. Normal play is continuous; internal set boundaries are not scored breaks. After trial 30 or 60, copy the known closed prefix, end protection at confirmed feedback offset, and checkpoint it before the next set. Keep a neutral checkpoint screen until exact durable confirmation; a healthy, visible, owned document starts the next set automatically. Hide while that checkpoint is pending leaves a neutral Continue gate, not an Invalid result. Ownership loss during the protected trial invalidates; loss after protection ends leaves the checkpoint gate and requires a fresh exclusive owner before Continue. A canceled owner acquisition releases or retires its pending callback and cannot start play later. If checkpoint confirmation fails, show review and Retry; never auto-advance. A reload ends the existing run as incomplete review, never resumes a partially completed set, and a new start receives the next form.

Keyboard defaults to physical `ArrowLeft` for short and `ArrowRight` for long. Optional remapping must choose two distinct ordinary physical codes from the V1.0 allowlist and pass a fresh keydown/keyup input check for each side. During scored play reject repeat, composition, modifier chords and keys held across Start/fixation/onset; keyup rearms. Pointer mode uses two large response controls: only primary `pointerdown` with button 0 and one active pointer ID is eligible; simultaneous contacts are ignored, and window-level `pointerup`/`pointercancel` releases a held contact even outside the control. A following click does not count twice; click-only or unknown-source activation can use untimed learning but cannot enter timed play until the chosen source passes the fresh input check. Native Enter/Space activation remains available for all untimed controls. Focus moves to each untimed heading/action and remains visibly indicated; timed play uses a neutral status cue without moving focus into the hidden answer. No unrelated raw keys are persisted. The chosen input class/codes, pointer type where relevant, alternative-input declaration, visual family, contrast/magnification declarations, browser and viewport context are frozen at arm; a protected mid-run change invalidates. Nonvisual mouth discrimination is not claimed: candidates requiring a spoken distinction may use the untimed guide but cannot start timed V1.1. Modified/alternative-input results are labeled separately.

Use one monotonic `performance.now()` clock per document. Start acquires exclusive ownership and commits/readbacks the exact arm before fixation. For each trial, immediately write a neutral fixation and confirm its connected visible frame. At `fixationConfirmedMs + 500`, write the face and confirm connected visible onset. The face is shown for **180 ms** from confirmed onset, then removed and its absence confirmed; responses remain accepted after removal until `onsetMs + 1,300`. The first fresh selected-side action in `[onsetMs, onsetMs+1,300)` is the sole answer; a later selected action is factual extra, never another answer. At exactly 1,300 or later the unanswered trial is omitted. If a response arrives before face removal, retain it but do not start feedback until removal is confirmed. Otherwise begin feedback after the first response and confirmed removal, or after the deadline for an omission. Feedback lasts **500 ms from its confirmed onset**; if and only if a preassigned opportunity was answered correctly, show an original `+50¢ simulated` reward message and update the running total. No correctness or missed-opportunity message appears on other trials. The next fixation follows confirmed feedback offset; set checkpoints may add an untimed wait. The face is not redrawn to give another chance.

The due/actual/lateness rules and protection boundary are specified in the transition table below. A required stage or foreground protected-frame gap over 250 ms invalidates; over 50 through 250 ms records a quality note and excludes that trial's response time. Exactly 50 ms is clean and exactly 250 ms is a note, not invalidation. A separate 2,000-ms watchdog from each original required-stage due time invalidates at its first runnable check at/after the boundary if confirmation is still absent; OS suspension is not a wall-clock guarantee. A late callback cannot erase a watchdog failure. A stale callback cannot create a second onset, answer, reward or completion. Hide, blur, freeze, page exit, ownership loss, input/profile change and layout failure during protected play invalidate. Untimed preparation and a halted checkpoint gate do not invalidate solely due to elapsed time. Before Start, every onset and continuation, verify the measured SVG face and response controls are connected, visible, fully within the visual viewport and unobscured by app overlays; the SVG rendered width must be at least 240 CSS pixels, with no timed-play scrolling. If it cannot fit, disable timed play with a clear explanation while leaving guide/history usable. SVG geometry attributes necessarily encode a mouth line for rendering; answer-bearing DOM labels, metadata and speech are forbidden during timed play.

### Trial transition and evidence table

All `due` and `actual` times share the live document's monotonic clock. The ordered journal is ordered by observation time, not by a fixed event-type list. A response may legitimately precede `face_removed`; an early selected action may precede `face_presented`. Persist the observed event immediately with its actual handler time, never delay or reorder it to fit a template. At the same sampled time, sequence numbers give the observed handler order.

| Stage | Original due / transition | Mandatory confirmation and evidence |
|---|---|---|
| `set_started` → fixation | Accepted Start/Continue time for the set's first trial; otherwise the previous trial's confirmed feedback offset. | Write neutral fixation, confirm a connected visible frame at/after due, append `fixation_confirmed` with due/actual/lateness. Protection starts at accepted Start/Continue, before this write. |
| Face onset | Confirmed fixation + 500 ms. | Write one face, confirm connected visible onset on a frame at/after due, append `face_presented` first. A selected action at exactly onset may then be a response. If a failure is seen on that same frame, append `invalidated` after the factual onset. |
| Face removal | Confirmed onset + 180 ms. | Remove the face, confirm absence on a frame at/after due, append `face_removed` with due/actual/lateness. A response before this point remains in its actual earlier journal position. |
| Resolution | With response: `max(firstResponseHandlerMs, faceRemovedActualMs)`; with no response: confirmed onset + 1,300 ms. | At/after due, append `trial_resolved` with due/actual/lateness and chosen side or omission. For the omission branch, append `omission` at the first runnable check at/after the deadline, before resolution, retaining that actual observation time rather than fabricating a deadline-time callback. If a selected response arrives at or after the deadline, record a boundary extra, not an answer. |
| Feedback onset | Confirmed resolution actual time. | Write neutral feedback or the positive reward message, confirm its visible frame and append `feedback_presented` with due/actual/lateness. On an eligible correct trial, append one `reward_earned` and update the running total in that same admitted transition; otherwise neither a reward nor a correctness hint is shown. |
| Feedback offset and close | Confirmed feedback onset + 500 ms. | Remove feedback, confirm absence, append `feedback_offset` with due/actual/lateness, then `trial_closed`. This is the earliest next-fixation or set-checkpoint point. A completed final set appends `session_completed` only after trial 90 is closed, then captures immutable terminal bytes including that event. |

The first eligible answer or omission resolves the choice; later selected presses before `trial_closed` are factual extras and cannot alter it. During feedback, selected keydowns/pointerdowns are ignored for scoring but may be counted as `feedback_extra`; selected releases must still rearm the control for the next trial. A late deadline callback cannot convert an already accepted response to omission or omit an already invalidated trial. Every stage confirmation has a required event bearing due/actual/lateness, including feedback onset/offset and `trial_resolved`. Each stage's quality note and each protected frame-gap note is attributed to the current trial (fixation/onset to its following face; feedback offset to the just-closed trial); only that trial's reaction time is excluded. If a watchdog/lifecycle failure occurs, append factual confirmed stages first, one `invalidated` terminal next, cancel pending callbacks and capture immutable bytes; no later `trial_closed`, reward or next onset may be invented. At final feedback offset, protection ends only after the terminal prefix is copied. At nonfinal set feedback offset, protection ends only after the checkpoint prefix is copied; a hide before that point invalidates, a hide after it leaves a neutral checkpoint gate.

## 4. Ordered evidence, authority and recovery

Every event has schema version, installation/session/form/family identity, contiguous sequence, document clock domain and monotonic sampled time. Trial events also have one-based trial/set identity. `prepared`, `form_assigned`, `armed` precede scored play; `set_started` precedes its first fixation; each trial obeys the transition table's **partial order**, allowing `response` before `face_removed` and selected early actions before `face_presented`. The mandatory stage events are `fixation_confirmed`, `face_presented`, `face_removed`, first `response` or `omission`, `trial_resolved`, `feedback_presented`, `feedback_offset`, then `trial_closed`, subject to the permitted early-response position; selected early/repeat/extra/boundary/feedback actions and releases retain their actual observed positions. Append `reward_earned` only after confirmed positive feedback onset on an eligible correct trial and before `trial_closed`. `set_checkpoint` follows its thirtieth or sixtieth `trial_closed`; `set_continued` precedes the next set's first fixation. Quality/lifecycle events occur when observed, and exactly one `invalidated` or `session_completed` terminates a terminal journal. Every required stage event includes due/actual/lateness; a response includes chosen side, source and handler time. Hidden reward eligibility is established by canonical manifest, not by a candidate-facing event before payout. `reward_earned` records exactly 50 cents and resulting balance. The journal is append-only; every report derives from canonical form and immutable events. No employer or account identity is recorded.

Use a separate versioned `assessment-practice-lengths-mouth-v1-1` IndexedDB root with installation ID, revision, standard/accommodation counters, attempts, tombstones and separate report-view activity. V1.0's database remains intact. Each accepted arm transaction checks current installation and unique request/session IDs and atomically writes the assigned form, complete profile and three-event prefix. Start requires completion plus exact readback. Lost delivery retries use the same ID; unavailable readback means Start unconfirmed and no fixation. Each set checkpoint atomically stores the full known prefix, closed count and factual review, then verifies exact bytes before continuation. A failed/undelivered checkpoint shows retained review with a retry; it cannot silently advance. Terminal save copies immutable bytes, commits, and confirms exact current-root readback before displaying Saved. A failed/lost write remains unsaved/uncertain until authoritative same-byte recovery. Individual deletion tombstones its attempt and removes report/activity; Delete all V1.1 replaces its installation. Legacy V1.0 deletion remains separate; a future global clear must clear both and report partial failure rather than claim full deletion. Every delayed write rechecks current installation, tombstone and target revision within its transaction; notifications are advisory. A visible report must revalidate authority at publication and withdraw saved aggregates if deletion/replacement is learned. Two tabs cannot own the same live attempt. On reload, an arm/checkpoint without confirmed terminal is **Incomplete, review-only, later exposure unknown**; no attempt is inferred omitted from absent events.

**Ordered authority boundary:** Exact readback alone never authorizes a later visible action. Start, every face onset (including after checkpoint Continue), visible report/history admission, individual deletion and installation replacement share one cross-tab data-order lock or an equivalent atomic revision claim. The actor checks the current installation ID, target tombstone, revision and required immutable prefix **inside the boundary**, performs the visible mutation and confirms its DOM state before releasing it. No unrelated storage wait occurs inside response/input resolution; the short ordering wait occurs before a face is exposed or a report is published. A report may keep already published numbers during a fast healthy authority check, but if that check remains unresolved after one complete rendering cycle it hides numbers until a current positive check; an older positive callback cannot restore a retired result. A deletion that orders first blocks the new onset/publication, retires the target and preserves already confirmed factual observations for review. If onset/publication orders first, it is retained as an observed fact; subsequent deletion withdraws saved eligibility and numbers before any later publication or face onset. Every subsequent trial checks current authority in its own onset boundary. Without notifications, a pending or late read cannot justify later exposure; a notification is only an early hint to check. Deletion completion may wait for a bounded in-progress onset/publication boundary, never indefinitely for a held callback or suspended tab. A watchdog/cancellation aborts its boundary and releases the lock; its late callback is fenced. A canceled acquisition cannot retain a lock or publish after a newer route. This same policy applies to automatic set continuation and a manually accepted Continue after a checkpoint gate. The live owner is exclusive to one attempt and is released on terminal capture, invalidation or cancellation; a lost owner cannot continue without fresh acquisition and authority check. Scope authority by installation/session/request, not by a positive read's arrival order.

Opening a verified review appends an idempotent `report_viewed` activity event with a new view ID, next activity sequence, current installation/session and source surface; activity cannot alter timed bytes. Old/unsupported schema is non-destructively review-only. Deleting V1.1 data never deletes V1.0, Stop or another game's records.

## 5. Scoring, report and acceptance

A Valid run has exactly 90 manifest-matched presented/closed trials, three sets, one first eligible response or omission per trial, one `session_completed` and no invalidation. `presented = closed + unresolvedPresented` and `90 = presented + unpresented` for every status. Invalid or Incomplete reviews show factual counts and reason but suppress aggregate accuracy, response-time and reward interpretation; already observed reward events and their simulated total remain factual. On Valid runs `correct + wrong + omitted = 90`. Show overall counts/percentages out of 90, short/long counts out of 45 each, and set counts out of 30 each; for each cell display its own integer counts and percentages using only that denominator. `responded = correct + wrong`; when it is positive, show short/long selected counts among responded trials, whose sum must equal responded. When responded is zero, show **“No response-side distribution”** with no `0/0` or fabricated percentage. A clean correct response time is handler time minus confirmed onset, within `[100,1300)`, with no affected quality note; show cells overall, by actual mouth category and by set. At least five values in that exact cell are required for a median and at least eight for median-of-halves IQR. Sort unrounded values. For odd `n`, exclude the central observation from both quartile halves; for even `n`, split into equal halves. Each half's median is its quartile. Compute before half-away-from-zero millisecond rounding; percentages round half-up to one decimal. Fewer than five values display “Not enough clean responses for a time summary”; five through seven show the median and “Not enough clean responses for variability.” The reward report shows count earned and simulated cents banked, by set and overall; `50 × earned = banked`, `0 ≤ earned ≤ 16`, with earned events possible only on the canonical eligible/correct subset. It does not show missed hidden opportunities, a psychometric reward-learning score or employer comparison.

The report includes validity, saved/unsaved/uncertain state, form/family/version, input/visual context, status reason, supported accuracy/reaction-time/reward counts, one task-specific practical observation, Replay, local V1.1 history/deletion and a link to separately labeled legacy bar history where available. The observation uses this deterministic order: if omitted ≥ 9, state the exact omitted count; otherwise if wrong ≥ 9, state the exact wrong count; otherwise state the exact correct count. It names this run only and offers no personality, improvement or reward-learning inference. Invalid/Incomplete reviews show factual status and a neutral review suggestion instead of this aggregate observation. No standard/accommodation or cross-version equivalence claim. It says `Advanced Training is not available for Lengths in this beta.` Mock integration is a later separate milestone: V1.1 is Game 7 in the versioned twelve-game sequence, and interrupted mock games restart from the beginning with the next form, never resume inside the game.
