# Stop V1.2 changed-path and acceptance plan

Base: clean `1f834dbd7c9c5b54f879997dab3b91145c9099c9`. Scope: the founder-approved Stop experience addendum only.

## Changed paths

- Preparation UI and local evidence: `Journey`, `Guide`, `Comprehension`, `Preflight`, `AssistiveInputNotice`, `preparation`, and Stop local storage. Preserve complete guide access; store and independently validate a versioned understanding pass before offering the optional shortcut.
- Timed orchestration: Stop `run`, engine, browser adapter, and `LiveRun`. Treat live warm-up as restartable preparation; enter full scored protection at accepted scored start, including initial fixation. Keep the current form, timing, scoring, routing, report, and drill contracts.
- Verification: focused deterministic preparation, interruption, admission, exposure, and UI tests; bounded browser observations; this QA record and tracker status.

## Acceptance checks

1. Prior current-version pass enables the shortcut after durable integrity checks; absent, deleted, corrupt and wrong-version evidence do not. The shortcut records its source and creates no example or question events. Setup, fresh input check, readiness and retest profile checks remain mandatory.
2. Long waits on every untimed screen and the handoff do not invalidate. A 30-minute retest reservation expires separately and requires reopening the explanation without a scored invalid result.
3. Hidden, lifecycle and compromising focus loss during live warm-up retain diagnostics and restart eight trials from trial 1 without form exposure. One timing anomaly restarts; a second ends preparation technically with no scored form consumption.
4. Handoff may pause. Scored start rechecks visibility, focus, key release, viewport, input/profile and reservation. Immediately before onset, hidden/focus/lifecycle invalidation leaves an invalid draft and unconsumed form; immediately after confirmed onset, the draft retains presentation and consumes the form.
5. Remapped-key text is consistent across the rule, examples, understanding check, setup, readiness and live reminder. Key capture gets focus, Tab and browser shortcuts work, visible and announced input-check outcomes agree. Every disabled control has a current reason and next step; assistive input blocks timed entry without a false personal warning for standard-keyboard users.
6. Run focused and existing deterministic tests, lint, build and bounded real-browser checks. Record source/build/browser limits; update the tracker, commit locally and hand off an exact SHA for independent audit. M6-C qualification remains separate.
