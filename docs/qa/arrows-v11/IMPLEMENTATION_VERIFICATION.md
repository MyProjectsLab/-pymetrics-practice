## Schema decisions

V1 roots failing the frozen V1 inspector are never migrated or rescored. They remain byte-preserved, new Start is disabled, unverified labels may be read, and explicit Delete all is available. New V1.1 tombstones are `{version:'arrows_spec_v1_1', ordinal, requestId, deletedAtWallMs}`. Existing numeric tombstones retain their V1 meaning. V1 live count plus numeric tombstones reconciles the old counter; V1.1 live/tombstone ordinals uniquely cover `1..scoredStartCountV11`.

Migration runs only after `ArrowsEntry.begin` acquires the existing live ownership lock, under the existing presentation/deletion order. Both inventories are verified before entering the synchronous IndexedDB transaction. Migration changes only root version, adds V1.1 count zero, and increments root revision once; arming then independently increments the V1.1 count/revision. A committed result whose delivery is lost requires authoritative exact readback.

## Evidence limits

Structured-clone equality and serialized historical journal/snapshot fixtures establish retained logical bytes; IndexedDB does not expose stable raw disk bytes. Browser tests use local Chromium headless, scripted browser input, injected callbacks/lifecycle and actual IndexedDB. Pure fixtures and modeled Web Locks establish precise ordering expectations; they do not certify natural device latency, native touch, assistive input, screen readers, suspension or the full supported browser/device matrix. An admitted block may briefly continue in memory until it observes deletion when notifications are absent; saving, Continue and report publication still require current authority. No cross-version comparison or calibrated equivalence is claimed.
