# Limited assessment summaries v1 — 25 October 2026

The founder explicitly approved adding performance summaries to Pietro's existing Umami account after the scope was explained. This versioned addendum changes the earlier no-performance-collection boundary only for the closed scalar schema in `src/assessment-usage/contract.ts`. It does not change or rewrite the frozen Stop coarse-analytics contract, source packets, any game scoring, timing or local storage schema. The old Stop analytics client remains dormant.

One `assessment_outcome` event describes an observed fresh attempt reaching a confirmed ending. The source hook map and exact release evidence record the accepted native start and terminal authority. Current standard Practice and its ordinary mock paths are supported; no Advanced Training, Stop touch practice, legacy report or history backfill is included. Unsupported modes are omitted rather than identified by accommodation choice.

Completed summaries carry only task totals, version/context and completion status. Money Exchange is completion-only. No individual answers, response times, journals, participant IDs, employer, full URL/query, personal details or setup profiles are sent. Invalid/incomplete outcomes carry no performance fields. The registry gives integer bounds and units: Balloons and Easy or Hard money is cents; Cards amounts are dollars. Missing Digits maximum length means zero correct sequences. Arrows denominator is 135, Lengths 90, Faces 14, Stop 80, Cards 80, Keypresses target40; Digits is variable. Families are not calibrated equivalents.

The page-local ticket is admitted by a fresh accepted native start. Only its matching current terminal publication may consume it. Detailed reports never enter a network payload or persistent queue. The gate aborts task requests and transport timeouts before protected work. Projection takes place after protection ends; the bounded closed summary is sent after native publication/cleanup returns. Nothing awaits collection. Lifecycle loss or departure drops the ticket. A next action/start aborts pending delivery. There are no analytics timers, SDK calls, per-response instrumentation, retries, beacons or unload sends during protected work.

Only canonical HTTPS TraitGame task routes may collect. DNT/GPC disable it. Requests go to Umami's public collection endpoint with the existing Pietro website ID, omit credentials/referrer, and never consume provider session/visitor identifiers. Ordinary network metadata reaches the provider. The current verified Hobby allowance is 100K monthly events, six-month analytics retention, US data region. No purchase or upgrade is needed. Local history deletion cannot erase previously received provider summaries.

Counts mean recorded attempts, not unique people, validated population norms or employer scores. Hidden/closed/reloaded/unsupported/blocked/failed-delivery attempts leave gaps. There is no complete start/abandonment funnel or promise of exact once delivery over an unreliable network. A transport attempt is locally one-shot. A separate explicitly named `analytics_verification` event may validate live delivery without fabricating a completed assessment.
