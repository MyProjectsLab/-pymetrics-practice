## Reproduction and ordering

Before this edit, a focused browser/entry regression held the last positive authority-read delivery, then expected no scored Start; it failed because the browser published `block_started` and entered fixation. The independent audit supplies the real two-tab IndexedDB reproduction for first Start and same-request retry, with both deletion types.

The final authority read, accepted Start, immediate fixation insertion, and first confirmed scored onset now hold one stable short Web Lock. Individual deletion and Delete all use that same lock through their transaction and confirmation readback. If deletion commits first, Start reads the retired root and cannot present. If Start enters first, deletion cannot commit before the first onset confirmation. The browser returns from readiness when Start is accepted; its timed frames, input and resolution do not await storage. Cancellation and first-stage watchdog abort the held admission and release both the short ordering lock and long live-owner lock. A deletion confirmation that never settles is bounded to five seconds: its abort signal reaches the IndexedDB transaction, and the short lock releases with an uncertain deletion error. A committed but undelivered write is observed by the next authoritative read; a still-live transaction is aborted before its late callback may mutate the root.
