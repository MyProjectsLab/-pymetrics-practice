# Arrows A9 F1 — reentrant terminal listener

**Base:** clean `b600d73a056eda46e9ead6042fda571f8dbfabc9`. The [independent A9 audit](/private/tmp/arrows-a9-independent-b600d73/AUDIT.md) reproduced F1: after a confirmed Block 1 checkpoint, an Invalid/settings event published at the untimed break; its listener called `cancel()` or `dispose()`, and the adapter skipped terminal capture because it was already closed. The live journal had 150 events but durable storage retained only the 149-event checkpoint. Retry had no terminal result.

The adapter now retains the immutable terminal state **before** calling its publication listener. After the callback, it schedules exactly one terminal save even if the listener closed or disposed the run. Ownership release remains independent of storage completion. The technical-invalidation path likewise captures its terminal state before publication. A listener may request a save immediately; the normal post-publication path shares that pending promise.

**Developer checks:** two new regressions cover both reentrant `cancel()` and `dispose()` on a break invalidation, including a failed first write, same-byte retry, and exactly one ownership release. Browser input was scripted; the breakpoint was controlled.
