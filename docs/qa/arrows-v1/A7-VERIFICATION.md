# Arrows A7 — durable snapshot storage foundation

**Base:** clean `2e2851b702a026d301f19e3e9d6a8e39f6fc7abc`. The [separate A6 F3-R6 audit](/private/tmp/arrows-a6-f3r6-audit-2e2851b-j2zqll9p/AUDIT.md) passed its bounded browser-adapter scope. It did not establish a playable saved Arrows game.

This stage extends the existing Arrows installation root with an optional, versioned per-attempt snapshot. At an untimed break or terminal state, `saveSnapshot` copies the full known journal and independently reconciled headless review, checks the original arm and previous journal prefix inside the write transaction, then requires exact authoritative readback before returning a saved snapshot. A committed write with lost delivery can be recovered by readback. A rejected or unconfirmed write cannot claim success. An existing arm-only record remains readable without changing its bytes. The original arm provenance remains intact; snapshot revisions are monotonic and a terminal snapshot cannot be replaced. `loadSnapshot` revalidates the root and canonical form. Untimed continuation compares original arm provenance while allowing a verified checkpoint.

**Developer checks:** Arrows focused suite **54/54 passed**; lint passed with two inherited warnings; frozen form regeneration and production build passed. A bounded Chromium probe used real IndexedDB to save a 24-trial, 149-event break checkpoint, reload the page, and recover identical installation, revision, closed count, event count and incomplete headless status. Memory-backend fixtures cover lost delivery, failed precommit write, idempotent retry, terminal write, changed revision/prefix, changed saved evidence, deletion and replacement. Browser probe source is `/private/tmp/arrows-a7-storage-browser.mjs`; its output is external to the repository.

**Limit:** This is a storage API foundation. The live browser adapter does not yet call it; timed journals, candidate report/history and deletion UI remain future work. The saved review remains explicitly `headless_unconfirmed`, not a browser-valid candidate result. No whole-game acceptance, native timing, device/accessibility qualification, deployment or release is claimed. A separate exact-SHA read-only audit is required.
