# Arrows A10 P1-R1 — preserve authority loss from write recovery

**Base:** `6e30b62ab5596daf55559a1fbd5beb5970dd1cb6`. The [independent audit](/private/tmp/arrows-a10-p1-independent-6e30b62/AUDIT.md) found that `saveSnapshot()` could catch an operational write-delivery failure, observe actual deletion or installation replacement during its fallback read, discard that stronger evidence, and propagate only the original operational error. A retired terminal could consequently retain `saved` status and accept an older positive read.

The storage layer now has one explicit authority-loss classifier for installation replacement and original-arm/snapshot-prefix changes. The browser adapter uses that same classifier. During failed-write readback, storage propagates a proven authority loss; it still returns exact committed bytes when the original arm/result remains authoritative and still treats unavailable readback or revision conflicts as retryable uncertainty.

Lint, frozen-form check, TypeScript/production build and `git diff --check` passed; lint retained two inherited warnings. Bounded Chromium `145.0.7632.6` reran the auditor's four failed-delivery retirement cases and two intact-root controls against a fresh adapter bundle with real IndexedDB and Web Locks; **6/6 passed**. The adapted drivers and raw results are under `/private/tmp/arrows-a10-r1/failed-delivery-readback.*` and `/private/tmp/arrows-a10-r1/failed-delivery-controls.*`. The delivery failure and mutation boundaries were injected; physical input/timing was not measured.
