## Changes within F1–F5

- **F1:** Delete all deletes every property of the transaction's root before assigning the fresh installation. Optional training, chains, journals and embedded baseline data disappear in the same transaction as scored records and exposure. Tests compare the entire replacement shape/values and verify old assignment/action/pause/restart writes cannot change it.
- **F2:** Training acquires the existing installation-wide browser owner lock, shared with Practice. Assignment/recovery atomically sets an attempt-bound token and increments the durable generation. Every action, recovery read, pause and restart checks the live capability, installation, owner ID, attempt and generation. Polling never creates a token. New owner recovery first pauses the committed attempt; Resume verifies again. Release invalidates the in-memory capability and frees the browser lock; the durable owner row is a fence, not evidence that its browser lock remains held. A subsequent acquisition advances generation. Tokens are published to the caller only after transaction delivery, avoiding phantom tokens on abort. Repeated invalid restart returns the current successor or first completed attempt; concurrent pending delivery cannot create a second successor. New adapter-generated journal commands record their checked generation through a backward-compatible optional field; historical headless journals remain readable.
- **F3:** Drill Type text and stripe/dot/grid identity use the existing fixed mapping/CSS. Focus moves to Next/Continue after outcomes, Pump after Start/Next/Resume, and the existing history action after completion. A persistent polite region announces Type, current/banked values and outcomes; standard mode omits successful pumps, verbose mode includes them. Native clicks remain the only action entry. The enclosing Practice input guard is suspended only while training is mounted, preventing two guards from consuming each other's key releases. The drill guard survives saves and polls. Healthy polls do not disable focused controls; action transactions independently enforce current authority.
- **F4:** Blur/hidden delivery synchronously blocks input, cancels the current key cycle and fences pending continuations. A separate transaction pauses the authoritative committed prefix. Successful recovery preserves that round, pumps, totals and results; Resume requires a fresh activation and a verified owner. A write failure pauses recovered durable state; a committed final completion remains complete and retains exactly one lock. Failed/unavailable pause authority is shown as needing checking, not falsely saved/paused. Late callbacks cannot re-enable the old operation. Deletion notifications immediately withdraw the view and require fresh reopening.
- **F5:** Attempt construction receives reconciled history across the installation for familiar-inventory labeling. Current-attempt and first-completion selection remain chain-specific. An unstarted prior attempt does not count; started invalid/completed attempts do. First-use copy describes the current attempt without claiming that its inventory remains unstarted after Start.

Router arithmetic, fixed inventories, feedback mathematics, first-completion eligibility rules, B1-B mechanics, Stop source, analytics configuration and governing documents are unchanged. No retest, comparison, mock, analytics activation or release work was added.
